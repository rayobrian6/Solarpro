# v47.423 — Brand-Agnostic Panel Auto-Swap + UI Education

## Intent (user quote)

> "The system should be automatic on the switch. Maybe throw out a panels
> auto switched. If wanting to change panels, look at compatible panels.
> Auto fixing and educating sounds the best for me. Any fix you do needs
> to work downstream too when we add on different brands. I don't want to
> fix this multiple times. I want seamless brand onboarding."

## Problem

When a user loads a project whose panel (e.g. Q CELLS Q.PEAK DUO BLK
400W, Isc 12.26 A → NEC design 15.33 A) was selected before they switched
to an ecosystem with a stricter per-MPPT cap (e.g. Growatt, 13.5 A), the
engineering page surfaced opaque "MPPT_CURRENT_EXCEEDED" errors and
showed a stale "3 strings (12/str recommended)" label that didn't match
the Auto-Apply config of 2 strings × 9.

## Tiered fix (user-approved Option C — Tiered)

| Status       | Trigger                                   | Action                                    | UI                       |
| ------------ | ----------------------------------------- | ----------------------------------------- | ------------------------ |
| compatible   | ≥15% MPPT current headroom                | silent pass                               | nothing                  |
| marginal     | 0–15% headroom                            | warn                                      | yellow banner            |
| incompatible | design current > cap, suggestions exist   | **auto-swap** + explain                   | blue banner with "Why?"  |
| incompatible | design current > cap, no suggestions      | hard warn                                 | red banner               |
| unknown      | brand has no resolvable per-MPPT cap      | fail-open                                 | nothing                  |

## Brand-agnostic architecture

### Gate module — `lib/system/panelCompatibilityGate.ts`
- `getBrandMinMpptCurrent(brand)` scans `brand.supportedInverterModels`,
  resolves each `equipmentDbId` against `STRING_INVERTERS`, and returns
  the minimum `maxInputCurrentPerMppt`. Zero per-brand logic.
- `evaluatePanelBrandCompatibility(panel, brand, options)` returns a
  `PanelCompatibilityGateResult` with status, suggestions (via existing
  `findCompatiblePanels`), headroom %, and a UX-ready reason string.

### Sizing-engine integration — `lib/system/sizingEngine.ts`
- `SizingInput` gains optional `panelId`.
- `SystemSizingResult` gains optional `panelCompatibility` carrying the
  final verdict + ranked suggestions.
- `sizeSystemFromBrand()` runs the gate AFTER brand resolution but
  BEFORE inverter sizing. Incompatible panels are auto-swapped by
  cloning `SizingInput` with the top-suggestion panel's electrical
  specs; every downstream step sees a compliant design.
- Warnings:
  - `PANEL_AUTO_SWITCHED` (info) — swap happened
  - `PANEL_MARGINAL` (warning) — tight fit, no swap
  - `PANEL_INCOMPATIBLE` (warning) — no catalog suggestion
  - `MULTI_UNIT_CONFIGURED` (info) — softens legacy
    `FEASIBILITY_NO_VIABLE_MODEL` noise when sizer rolls up to >1 unit
  - `FEASIBILITY_ROLLED_UP_MULTI_UNIT` (info) — replaces the scary
    original code when multi-unit softening applies

### UI — `components/engineering/PanelCompatibilityBanner.tsx`
- Single component handles all three tiers, palette-switched.
- Expandable "Why?" reveals brand cap, headroom, top-3 replacements.
- Each suggestion is click-to-apply; invokes `onChangePanel(panelId)`
  which the engineering page wires to `setConfig`.

### Collapsed inverter card header (Bug A)
- Previously read the global `computedSystem` → showed stale
  "3 strings (12/str recommended)" on every card.
- Now derives from `inv.strings` so each card reflects its own config:
  "2 strings (9/str)" or "11/12 panels" for asymmetric layouts.

## Future brand onboarding

Adding a new brand (Solis / Schneider / Victron / OutBack) requires ZERO
changes to this subsystem. The gate's `getBrandMinMpptCurrent()` scans
`BRAND_PROFILES` at runtime. As long as a new brand registers its
`supportedInverterModels` with resolvable `equipmentDbId`s pointing to
`StringInverter` entries that have `maxInputCurrentPerMppt`, the gate
automatically protects users from incompatible panels on that brand.
