# Source-of-Truth CAD / Render Audit V1

This audit documents the current deterministic SVG plan-set preview path before the Source-of-Truth CAD Generation Pipeline refactor. It is intentionally limited to preview/render behavior and does not grant CAD, permit, engineering, BOM, or construction authority.

## Scope and Entry Points

The current A-101 sheet is generated by `buildProfessionalPlanSetRenderPackage(report)` in `lib/siteSurvey/planSetRenderOutput.ts`. Its only required input is `ProfessionalSurveyReadinessReportV1`, which is produced from site-survey data, parsed survey evidence, canonical geometry, CAD readiness, geometry intelligence, photo evidence, render readiness, and render recommendations.

Photo evidence enters the A-101 render path through `buildContext(report)`, which calls `buildEvidenceDerivedCadReconstruction(report)`. That reconstruction adapter builds photo frames, photo-aligned candidates, fallback-only candidates, evidence alignment metrics, and no-authority declarations. A-101 renders those candidates with `renderEvidenceDerivedOverlays(ctx)`.

Canonical roof geometry enters A-101 through `report.canonicalGeometry.roofPlanes`, which is consumed by `renderRoofGeometry(ctx)`, `renderSetbacks(ctx)`, `renderModulePreview(ctx)`, `renderRailSymbols(ctx)`, `renderLeaderCallouts(ctx)`, and bounds/viewport helpers. This geometry is survey-derived metadata, not stamped CAD authority.

Existing design/system truth exists outside the current A-101 builder in `lib/system/systemDefinition.ts`. The relevant contracts are `SystemDefinitionInput`, `buildSystemDefinition(input)`, `SystemDefinition`, `PanelDefinition`, `LayoutDefinition`, `ElectricalDefinition`, `SysDefObstruction`, and `SysDefElectricalNode`. These can supply panel dimensions, wattage, orientation, total panel count, tilt, azimuth, row spacing, inverter topology, string size, system power, main panel amps, equipment selection, and optional design/vision/manual obstruction and electrical nodes. The current A-101 builder does not accept or consume these design/layout objects.

Existing layout/array derivation support also exists in `lib/multiArrayEngine.ts` through `buildArraysFromLayout(layout, lat, lng)`, which can preserve existing arrays/panels when supplied. The current A-101 builder does not use this handoff.

## Required Classifications

The required source classifications for render layers are `survey_photo_truth`, `survey_metadata_truth`, `design_3d_truth`, `design_layout_truth`, `equipment_truth`, `inferred_review_required`, and `fallback_placeholder`.

## Current Panel Count and Placement Behavior

A-101 currently does not read a design panel count. For roof systems, it renders a generated module grid per canonical roof plane using bounds-derived row/column counts. For ground systems, it renders a fixed 3 by 7 module preview. For fence systems, it renders fixed linear bay previews. These module previews are not sourced from `SystemDefinition.layout.totalPanels`, existing arrays, existing panels, or design layout planes.

The required correction is to introduce a preview-only design handoff that preserves design-owned fields and consumes them read-only. When a design handoff is present, A-101 should display design-derived panel count, panel dimensions, orientation, grouping, install plane association, system/equipment selection, inverter topology, and available electrical/equipment nodes. When that data is missing, the fallback must be visible, scored down, and marked review-required.

## Current Photo Evidence Behavior

A-101 uses photo evidence only through the evidence-derived reconstruction overlay and electrical/coverage dimming. Photo evidence can produce roof edge candidates, install area candidates, obstruction candidates, equipment anchors, conduit anchors, module alignment cues, and orientation/depth cues. However, these candidates are not yet reconciled with design layout or canonical roof geometry, and they do not yet provide formal layer provenance for every visible A-101 layer.

The required correction is to promote the existing photo evidence path into the primary source-of-truth context for render layers while keeping it non-authoritative and review-only. Photo-derived candidates should influence visible roof edge evidence, obstruction evidence, equipment/meter/MSP anchors, conduit anchors, install-area confirmation, and warning callouts without mutating canonical geometry or design data.

## Current Design/3D/Layout Behavior

The current A-101 render package has no design/layout parameter. It does not call `buildSystemDefinition`, does not consume `SystemDefinition`, and does not consume existing arrays/panels from layout data. This means panel count, module placement, module orientation, equipment selection, inverter topology, and string/group metadata are either missing from A-101 or represented by synthetic preview symbols.

The required correction is to add a new optional read-only source-of-truth handoff input to the render package builder. The handoff should classify design-derived data as `design_layout_truth`, `design_3d_truth`, or `equipment_truth`, carry source references, and never mutate the source project/layout/system objects.

## Current Fallback/Synthetic Assumptions

The current A-101 still includes synthetic site context, property boundary, driveway, neighboring structures, module layouts, ground/fence fixture geometry, roof obstruction symbol, rails/attachments, equipment position, conduit path, string/group labels, grade lines, trench paths, support posts, gate zones, scale/north graphics, and generic construction notes. Some of these are useful drawing aids, but none may masquerade as source-derived CAD.

The refactor must make each fallback visible and penalize hidden fallback assumptions in quality scoring. Decorative render density must not improve the score unless it is traceable to survey photo truth, survey metadata truth, design truth, equipment truth, or clearly disclosed review-required inference.

## Required Reconciliation Checks

The source-of-truth context must detect and expose at least the following review conditions: design panel count missing, generated/fallback panel layout used, design panel count not equal to visible module count, design tilt/azimuth inconsistent with canonical roof planes, missing survey photo confirmation for install area, missing obstruction evidence, electrical/equipment coverage without location anchor, equipment node without photo support, survey evidence candidate without design mapping, design layout without survey support, and any fallback placeholder rendered on A-101.

## Safety Boundary Requirements

The refactor must preserve the current no-authority boundary. It must not promote photo extraction to engineering authority, mutate canonical geometry, overwrite design data, auto-correct layout, run CAD solver authority, generate stamped permit documents, trigger downstream flows, or hide fallback/synthetic layers. All outputs remain preview-only, review-first, traceable, source-of-truth aware, and non-authoritative.

## Implementation Targets Derived From Audit

1. Add source-of-truth DTOs for design handoff, layer provenance, reconciliation, and authenticity metrics.
2. Add a read-only design/system/layout handoff mapper that can consume `SystemDefinition` and optional raw layout/design metadata.
3. Add reconciliation between design handoff, survey photo evidence/reconstruction, canonical geometry, and render readiness.
4. Change A-101 module rendering to prefer design-derived panel count, dimensions, orientation, grouping, and plane association; otherwise render disclosed fallback only.
5. Attach provenance to every visible A-101 layer through SVG titles/descriptions and a visible source-of-truth legend/table.
6. Replace generic legend and scoring with truth traceability, survey photo usage, design usage, fallback disclosure, reconciliation status, and no-authority checks.
7. Add tests for design handoff, photo handoff, layer provenance, A-101 provenance, reconciliation, fallback disclosure, scoring, and safety boundaries.
