# v47.415 — Real SolarEdge Design Rules (Research-Based Fix)

## What I was getting wrong

I've been using `optimizerMaxOutputCurrent = 15.0 A` as the
per-string MPPT allocator current for SolarEdge optimizer systems.
That is the **optimizer's nameplate max output current at the bus**,
but it's the current the string delivers only when the string is at
its MAX POWER — e.g. 25 panels × 240 W = 6,000 W / 400V = 15 A.

For a 9-panel × 400W string (like this customer's 36-panel system on
2× SE7600H-US), the actual operating current is:

    stringOperatingCurrent = stringPower_W / inverterNominalDcV
                           = (9 × 400W) / 400V
                           = 3,600 W / 400 V
                           = **9.0 A**

Not 15.0 A. That's why the manufacturer allows 2 strings per
SE7600H-US even though 2 × 15A looks like it exceeds 20A — because
**at 9 panels per string the actual current is 9A, and 2 × 9A = 18A
≤ 20A**.

## Source of Truth

SolarEdge Application Note "SolarEdge String Sizing, North America":
https://www.solar-electric.com/lib/wind-sun/se_optimizers_string_sizing.pdf

> "Maximum string power is simply the 'Inverter Nominal DC Input
> Voltage' multiplied by the 'Optimizer Maximum Output Current'."

For SE7600H-US: 400 V × 15 A = **6,000 W max per string**.

SolarEdge SE7600H-US datasheet:
https://media.unboundsolar.com/app/uploads/media/2019/12/08165624/solaredge-se7600h-hd-wave-inverter-specs-20190311174102.9995976-1.pdf

- Nominal DC Input Voltage: **400 V** (fixed)
- Max Input Current: **20 A**
- Physical string inputs: **1-2 strings** (per install spec)
- Max DC Power (oversize): 11,800 W

SolarEdge P-Series optimizer datasheet:
- Max output current per optimizer: **15 A**
- Operating output voltage: **60–85 V per optimizer**
- Safety output voltage (standby): **1 V per optimizer**

## Two different "design currents"

For optimizer topology there are TWO different current values with
TWO different purposes, and I have been conflating them:

### (A) NEC 690.8(A)(2) "design current" — for wire ampacity + OCPD sizing
Value: **optimizer nameplate max output current = 15 A**
This is code-minimum "maximum circuit current" — the conductor must
handle the optimizer's rated max output even if operating current is
lower. The OCPD is sized from this × 1.25.

### (B) MPPT allocator "operating current" — for feasibility placement
Value: **min(optimizerMaxA, stringPowerW / inverterNominalDcV)**
For 9 × 400W panels on SE7600H: min(15, 3600/400) = 9 A
This is what actually flows through the MPPT channel at steady
state. The allocator uses this to decide whether N strings can share
a channel without the inverter's software-regulated 20A cap kicking
in (which would cause clipping, not failure).

## What the fix looks like

1. **Add `nominalDcVoltage` field** to inverter equipment records
   (fallback to midpoint of MPPT range if absent).

2. **Add `operatingCurrentPerString` helper** that returns:
   ```
   if (topology === 'optimizer' && inverterNominalDcV && stringPowerW) {
     return min(optimizerMaxOutputCurrent, stringPowerW / inverterNominalDcV);
   } else if (topology === 'optimizer') {
     return optimizerMaxOutputCurrent;  // fallback, conservative
   } else {
     return panelIsc × 1.25;
   }
   ```

3. **In feasibilityEvaluator** — pass `operatingCurrentPerString` to
   the MPPT allocator's per-string `designCurrent`. Keep
   `optimizerMaxOutputCurrent` for NEC wire/OCPD sizing.

4. **In string-generator.ts, electrical-calc.ts, computed-system.ts**
   — same split. Operating current for MPPT feasibility; optimizer
   cap for NEC conductor/OCPD.

5. **In feasibilityEvaluator per-string check** at line 272 —
   compare `operatingCurrentPerString` (not 15A) against
   `maxInputCurrentPerMppt`. A single 9-panel string draws 9A; a
   single 20-panel string draws 8kW/400V = 20A; the check correctly
   catches strings that exceed the channel cap individually.

6. **Update recommendedStringRange** for SolarEdge models in the
   equipment DB from `{ min: 8, max: 13 }` to `{ min: 8, max: 25 }`
   to match datasheet, BUT add a power cap of 6,000 W per string
   enforced by the layout planner.

7. **Add a new constraint: `maxStringPowerW` per inverter model** —
   6,000 W for SE7600H-US, 5,700 W for SE3000H–SE6000H.
