## Math Check

- **36 panels total** (3×10 + 1×6)
- **Per-string design current = 15.3 A** (= panel Imp × 1.25 NEC factor, so panel Imp ≈ 12.24 A → this is a high-current N-type panel, e.g. Jinko Tiger Neo 580, Canadian Solar HiKu7, Qcells Q.Tron)
- **MPPT limit = 20.0 A** (matches `maxInputCurrentPerMppt: 20.0` — see `equipment-db.ts:403`, `813`, `851`)
- Per channel, 2 strings would draw 30.6A → exceeds 20A → only 1 string fits per channel
- With 2 MPPT channels: max placeable = 2 strings (20 panels max with length 10)
- **System has 4 strings → 2 unplaced → guaranteed failure**

## Expected Behavior (per v47.387 / v47.389 roadmap)

The **feasibility hard gate** (v47.387 `applyFeasibilityHardGate()`) was supposed to prevent exactly this by substituting a feasible inverter when the chosen one fails MPPT current checks. And v47.389 pre-computes the feasibility-rejected set before Rules 1/2 so upsize doesn't contradict feasibility.

**Why is this still escaping?** Hypotheses to investigate tomorrow:

1. **Hard gate bypass for micro/hybrid/optimizer paths?** Gate is opt-in — requires `panelIsc + panelTempCoeffVoc non-null`. If the panel spec is missing one of those fields, the gate falls through silently.
   - Action: check `equipment-db.ts` for panel rows missing `Isc` or `temperatureCoefficientVoc` — particularly high-current N-type panels.

2. **Engineering API passes single-inverter `maxInputCurrentPerMppt` but multi-unit setup?** Similar to v47.391/v47.392 bug class — the compliance tab shows 2 MPPT channels (single 2-MPPT inverter), not 4 channels (e.g. 2 units × 2-MPPT each). If the inverter is a 2-MPPT 20A-per-channel model like `se-10000h`, this is underpowered by design — the engine should have upsized to a 3+ MPPT inverter.

3. **The string generator produced 4 strings of 10/10/10/6 when 6 strings of 6 each would have been valid** (6 strings × 15.3A would still fail because only 2 channels).
   - Actually no: the fundamental issue is `totalDesignCurrent = 4 × 15.3 = 61.2A` vs `channelCount × 20A = 40A`. **No valid allocation exists with a 2-MPPT 20A inverter.** Only upsizing the inverter (more MPPT or higher per-MPPT current rating) resolves this.

4. **`FEASIBILITY_CHOSEN_INFEASIBLE` warning is missing from the error list** — meaning the hard gate either didn't run or didn't find a feasible alternative. This is the smoking gun.

- a) Hard gate isn't running (panel specs missing), OR

## Known Gotchas

- String design current is **per-string, not per-string-length**: shortening strings does NOT reduce current (contradicts the error message suggestion (c)). This is a misleading user-facing message that should also be fixed.
- DC/AC 0.95 warning + MPPT current errors together → user will be told to both "increase panel count" (DC/AC < 1.0) AND "decrease panel count" (MPPT overflow). Contradictory advice — UI should suppress DC/AC warning when MPPT gate fails.
