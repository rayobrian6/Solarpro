# v47.425 — Brand Onboarding Smoke Suite

**Goal:** Make brand onboarding mathematically safe. Any future brand added
to `BRAND_PROFILES` is automatically validated across every pipeline stage.
If ANY stage fails for the new brand, CI fails and the build is blocked.

## What the suite validates (per brand × per representative panel)

For every registered brand B, for a matrix of panels P spanning the
low/mid/high Isc range, the suite runs:

### Stage 1 — Structural validity
- Brand profile schema: required fields present, types correct
- `supportedInverterModels[].equipmentDbId` resolves in `STRING_INVERTERS` registry
- Every referenced inverter has `maxInputCurrentPerMppt`, `mpptChannels`,
  `maxParallelStringsPerMppt`, `maxDcVoltage`, `mpptVoltageMin`,
  `mpptVoltageMax`, `acOutputKw`
- Sizing tiers: no gaps, no overlaps, cover 0→Infinity
- Every tier's `inverterId` exists in `supportedInverterModels`
- ECOSYSTEM_BRANDS entry present (if brand is user-facing)

### Stage 2 — Panel Compatibility Gate
- `getBrandMinMpptCurrent(brand)` returns a positive number (or null for
  explicitly current-unconstrained brands)
- `evaluatePanelBrandCompatibility(panel, brand)` returns one of the known
  status values for every panel in the catalog (no crashes)
- When a panel is incompatible, either suggestions are non-empty OR a
  PANEL_INCOMPATIBLE warning is emitted with a human-readable reason

### Stage 3 — Sizing Engine
- `sizeSystemFromBrand()` does not throw for any valid panel count in
  {6, 12, 18, 24, 36, 48, 60} × any catalog panel
- Returns a non-null result with at least one sized inverter
- `panelCompatibility` payload is well-formed when `input.panelId` is provided
- If the gate swaps, downstream `effectiveInput` is used consistently

### Stage 4 — Compliance String Generator
- For every (brand, panel) pair where the gate gives a compatible result:
  `generateStringConfig()` produces ZERO `MPPT_CURRENT_EXCEEDED` violations
- No crashes, no NaN, no empty string lists

### Stage 5 — Auto-heal convergence
- The full-pipeline simulator (EngineeringPageSim) settles in ≤ 2 iterations
  for every (brand, panel) pair (no infinite loops)
- After settle, config.inverters[].strings[].panelId is consistent across
  all strings

### Stage 6 — Registry invariants (global)
- No brand has `supportedInverterModels` referencing a non-existent
  equipmentDbId
- No brand has overlapping sizing tiers
- Every ECOSYSTEM_BRANDS entry has a matching BRAND_PROFILES entry
- Every BRAND_PROFILES.topology is in the supported enum

## Why this closes the "future onboarding" guarantee

- **Zero per-brand code in the tests** — every test iterates over
  `BRAND_PROFILES` dynamically. Adding Solis/Schneider/Victron etc.
  automatically extends coverage.
- **Every major pipeline stage is exercised** — gate, sizing, compliance,
  auto-heal, registry.
- **CI-blocking** — the tests run in the main vitest suite. If any new
  brand fails any stage, `npm test` fails, the build is blocked.
- **Self-documenting failures** — each test names the specific brand and
  stage that failed, so a future maintainer immediately knows what to fix.
