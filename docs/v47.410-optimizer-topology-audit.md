## 4. Root cause diagnosis

The domain model has **one field** (`stringIsc`) that is being overloaded to mean two different physical quantities:

1. **Panel-method string current** — `Isc × 1.25` — correct for string inverters (NEC 690.8(A)(1))
2. **Optimizer-regulated string current** — optimizer cap — correct for optimizer systems (NEC 690.8(A)(2))

Today the field is populated with (1) always. v47.408 silently computed (2) inside one local variable (`designCurrentPerString`) and compared against channel current — but left the field (1) unchanged everywhere else. This means:

- The allocator passes, but the UI still shows the panel-method value.
- OCPD and wire-ampacity sizing still use the panel method (technically **over**-sizing for optimizer systems — safer but wasteful; probably fine for NEC, expensive for BOM).
- The permit PDF prints `Isc = 12.26A × 1.25 = 15.3A` next to an optimizer single-line that actually regulates at 15.0 A — **contradicts the SLD**.

## 5. Proposed fix (v47.410, single release, no more patching)

### 5.1 Core change: make `string-generator.ts` emit topology-correct values for ALL downstream fields

One source of truth: `designCurrentPerString` (already topology-aware). Derive ALL dependent values from it:

```ts
// AFTER:
const designCurrentPerString =
  topologyFamily === 'optimizer' ? optimizerCap : iscCorrected * 1.25;

// Use designCurrentPerString as the single source:
stringIsc:      designCurrentPerString,        // was: iscCorrected
totalDcCurrentMax: n_strings * designCurrentPerString;
ocpdPerString = roundUp(designCurrentPerString * 1.25);   // NEC 690.9 — 125% of max circuit current
dcWireAmpacity = designCurrentPerString;                   // Conductors sized at 156% of string current
// (×1.25 derate for continuous duty already in 690.8(A) via designCurrent)
```

Actually — `stringIsc` (the physical short-circuit current *into* the optimizer) is conceptually different from the optimizer-regulated *output* current. Two options:

#### Option A — Overload `stringIsc` (simpler, matches v47.408 implicit semantics)
Treat `stringIsc` as "string current for downstream electrical calcs." For optimizer systems this is the optimizer output. Document the semantic.

#### Option B — Add a new field (cleaner, breaks backward-compat at boundaries)
Add `stringDesignCurrent` (topology-aware) alongside `stringIsc` (always panel method). Update 29+ read sites to prefer the new field.

**Recommendation: Option A.** The ~15 downstream read sites are ALL asking "what's the current my string conductor carries?" — exactly what `designCurrentPerString` answers. Rename the comment and mean it consistently.
